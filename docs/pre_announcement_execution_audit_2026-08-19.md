## Scientific invariant checks added

### E1

The script now fails if:

- the tested monotone-accessibility cases exceed the configured FOSD numerical tolerance;
- monotone cases lose positive mean uplift;
- the independence null develops material mean uplift or correlation;
- the monotone control develops CDF crossing;
- either declared nonmonotone counterexample loses CDF crossing.

### E2

The script now fails if:

- the interaction-capable evaluator loses substantial predictive correlation/uplift;
- its mean predictive correlation no longer weakens as environmental noise increases;
- the misspecified linear or random controls develop material mean correlation or uplift.

### E3

The script now fails if:

- the recognition decomposition does not close to numerical precision;
- the recognition-label null is nonzero beyond numerical representation.

### E4

The script now fails if:

- the fixed-selector covariance identity does not close;
- rescue-bad, neutral, or amplify-good controls lose their intended interaction-sign behavior;
- the changing-selector decomposition does not close;
- the changing-selector control stops materially changing the selector map.

### E5

The script now fails if:

- the paired execution-strength decomposition does not close;
- the `q=0` recognition/execution null is not exact;
- cross-copy action-correlation increment stops increasing across the configured shared-environment sweep;
- the high-correlation coherence control weakens below the declared guard threshold;
- the single-copy total FP gain ceases to remain approximately flat across that sweep;
- shared and independent recognition no longer have closely matched marginal prevalence;
- shared recognition no longer increases cross-copy action correlation;
- the recognition-correlation contrast or matched-marginal FP control leaves its declared tolerance.

These are regression guards for the locked experiment mechanisms. They are not new empirical evidence and do not alter T1–T5 or the S2-family theorem statements.

## Reproducibility defect found and corrected

The repository required byte-for-byte figure/data regeneration while `requirements.txt` previously specified only lower dependency bounds. Under a different NumPy/pandas stack, all seven SVGs remained byte-identical but `fig2_fosd_theorem_illustration.csv` acquired a serialization-only byte difference.

A previous successful GitHub Actions run had generated the committed theorem-illustration CSV with Python 3.11.15, NumPy 2.4.6, pandas 3.0.5, and Matplotlib 3.11.1. The audit therefore aligned the byte-reproduction contract with an explicit environment:

- `.python-version`: `3.11.15`;
- `numpy==2.4.6`;
- `pandas==3.0.5`;
- `matplotlib==3.11.1`;
- GitHub Actions runner: `ubuntu-24.04`.

The workflow now executes the locked E1–E5 scripts under that environment and byte-compares every manifest-declared current reproduction CSV with committed `HEAD`. It separately byte-compares the committed SVG directory and deterministic Figure 2 theorem-illustration CSV after regeneration.

## Manifest/provenance validation defect found and corrected

The previous manifest validator checked only whether named CSV files existed. It did not reject missing/reordered experiment IDs, non-`LOCK` rows, duplicate declarations, or accidental overlap between locked historical and current reproduction classes.

The manifest validator now enforces:

- exact E1–E5 ID/order;
- unique experiment IDs;
- `LOCK` status for every core experiment;
- nonempty title/claim/theorem fields;
- CSV-basename and E-number consistency for current reproduction outputs;
- existence of every declared CSV;
- no duplicate file declarations;
- no locked/current provenance overlap.

Current-output byte validation is derived from the manifest rather than maintaining a second hard-coded list in the workflow. The reproduction validator additionally requires each current output to be tracked in `HEAD`.

Both validators were negative-tested locally: a one-byte mutation in a current reproduction CSV was rejected, and changing one manifest experiment from `LOCK` was rejected. After restoration, both validators passed.

## Semantic schema defect found and corrected

The E5 environmental-correlation reproduction previously emitted a field named `recognition_corr_increment`, but the code computed:

```text
avg_pair_corr(A_adapted) - avg_pair_corr(A_baseline)
```

which is an **action-correlation increment**, not a recognition-correlation increment.

The current reproduction schema is therefore corrected to `action_corr_increment`. The E5 generator and both SVG/PDF Figure 6 generators use the corrected field. The numerical data and plotted Figure 6 are unchanged. Locked historical CSVs retain their historical schemas and are not silently rewritten.

## Repository-structure validation defect found and corrected

The structure validator previously omitted several executable/configuration files from its required set. A repository could therefore lose files such as the workflow, experiment scripts, manifest, or dependency configuration while still reporting `Repository structure OK`.

The required set now includes the landing page, citation/dependency/Python configuration, validation workflow, E1–E5 executable scripts, manifest, theorem-illustration CSV, this execution-audit record, and all principal validation scripts in addition to the documentation/theory/figure surfaces already checked.

## Rendering checks

Repository Markdown uses fenced `math` blocks and the local Markdown validator checks fence balance plus structural TeX properties. CI also submits every Markdown file to GitHub's GFM Markdown REST renderer and checks preservation of headings, tables, and images.

The REST-renderer check is intentionally described as a **GFM structure check**, not proof that the final repository browser page has rendered MathJax or Mermaid correctly. Direct browser inspection remains required for:

- MathJax output;
- Mermaid diagrams;
- SVG sizing/readability;
- table/layout behavior on desktop and mobile.
